本篇目标

综合前面几种持久化方案，掌握本地数据设计的思路，能根据数据量、读写频率、安全要求选择合适的存储方式，理解缓存、离线优先、数据同步与迁移的基本策略。

一、四种持久化方案回顾

方案

特点

简单快速，不适合大量数据

选择原则：

  • 数据量小、结构简单 → UserDefaults

  • 数据量中等、需要序列化 → 文件读写

  • 对象关系复杂、iOS 原生 → Core Data

  • 查询复杂、性能要求高 → SQLite / GRDB

三、数据结构设计

设计步骤：

  1. 列出所有需要存储的数据。

  2. 按功能模块分组。

  3. 定义每个数据的字段与类型。

  4. 确定数据之间的关系。

  5. 确定读写场景与频率。

  6. 选择合适的存储方案。

四、数据模型设计原则

单一职责：一个模型只描述一类数据。

字段命名规范：

  • 用英文小写驼峰。

  • 语义明确，不要缩写。

  • 时间字段统一用 createdAt、updatedAt。

可选性设计：

  • 可能为空的字段设为可选。

  • 提供默认值，避免空值导致崩溃。

五、离线优先设计

离线优先（Offline First）：先读写本地，再同步网络。

流程：

用户操作 → 写入本地 → 界面立即刷新 → 后台同步服务器

优势：

  • 离线可用。

  • 响应速度快。

  • 弱网体验好。

关键设计：

  • 本地数据是主数据源。

  • 网络同步是后台任务。

  • 同步失败可重试。

  • 冲突有解决策略。

同步状态标记：

enum SyncStatus: String, Codable {
    case pending    // 待同步
    case synced     // 已同步
    case failed     // 同步失败
}

注意：

  • 不是所有应用都需要离线优先。

  • 简单应用可以先在线后本地。

  • 复杂同步逻辑需谨慎设计。

Keychain 简介：

import Security

func saveToKeychain(key: String, value: String) {
    let data = value.data(using: .utf8)!
    let query: [String: Any] = [
        kSecClass as String: kSecClassGenericPassword,
        kSecAttrAccount as String: key,
        kSecValueData as String: data
    ]
    SecItemDelete(query as CFDictionary)
    SecItemAdd(query as CFDictionary, nil)
}

文件加密：

  • 使用 CryptoKit 加密敏感文件。

  • 使用文件保护等级。

注意：

  • 不要明文存储密码。

  • 不要将敏感信息写入日志。

  • 不要将敏感数据上传到第三方。

九、避坑指南

  • 不要所有数据都放 UserDefaults：只适合少量键值。

  • 不要忽略数据迁移：版本升级必须考虑。

  • 不要明文存敏感数据：用 Keychain 或加密。

  • 缓存要有失效策略：否则会占满磁盘。

  • 不要在错误的线程操作数据库：注意线程安全。

  • 不要忽略分页：大数据量必须分页。

  • 不要忘记备份：用户数据丢失是严重问题。

  • 不要过度设计：简单场景用简单方案。
