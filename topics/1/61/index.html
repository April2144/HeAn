5.3 打包与上传

发布于 2026-09-19

实践项目

本篇目标

掌握 Archive 打包流程，能正确导出 IPA，使用 Xcode Organizer 或 Transporter 上传到 App Store Connect，并处理上传过程中的常见问题。

一、打包前的准备

检查清单：

  • [ ] 证书与描述文件配置正确

  • [ ] Bundle Identifier 与 App Store Connect 一致

  • [ ] 版本号（Version）已更新

  • [ ] 构建号（Build）已递增

  • [ ] 真机测试通过

  • [ ] 隐私政策已准备

  • [ ] App 图标与启动图已配置

  • [ ] 无编译错误与警告

版本号与构建号：

字段

位置

说明

General → Identity

对外版本号，如 1.0.0

General → Identity

内部构建号，每次上传递增

建议：

  • 版本号使用语义化版本：主版本.次版本.修订号。

  • 每次上传 App Store Connect，Build 必须比上一次大。

  • 可以只修改 Build，不修改 Version。

签名配置：

  • 确认 Team 选择正确。

  • 确认 Signing Certificate 有效。

  • 确认 Provisioning Profile 为 App Store 类型。

  • 若使用自动签名，确认 Automatically manage signing 已勾选。

清理项目：

Product → Clean Build Folder (Command + Shift + K)

二、选择目标设备

Archive 需要选择「Any iOS Device (arm64)」或「Generic iOS Device」。

操作：

  1. 在 Xcode 顶部工具栏，点击设备选择器。

  2. 选择 Any iOS Device (arm64)。

  3. 不要选择模拟器，否则 Archive 为灰色不可用。

注意：

  • 模拟器无法 Archive。

  • 真机也可以 Archive，但推荐选择通用设备。

  • 确保 Xcode 已识别到签名证书。

三、Archive 打包

操作步骤：

  1. 菜单栏选择 Product → Archive。

  2. 等待编译完成。

  3. 编译成功后，自动打开 Organizer 窗口。

编译过程：

  • Xcode 会执行 Release 构建。

  • 自动签名、打包。

  • 生成 .xcarchive 文件。

五、验证 App

验证步骤：

  1. 在 Organizer 中选择 Archive。

  2. 点击右侧「Validate App」。

  3. 选择分发方式：App Store Connect。

  4. 选择签名选项。

  5. 点击「Validate」。

  6. 等待验证结果。

验证内容：

  • 签名是否有效

  • 描述文件是否正确

  • 版本号是否重复

  • 图标是否完整

  • 隐私声明是否齐全

  • 是否包含私有 API

六、上传到 App Store Connect

方式一：Xcode Organizer 上传

  1. 在 Organizer 中选择 Archive。

  2. 点击「Distribute App」。

  3. 选择「App Store Connect」。

  4. 选择「Upload」。

  5. 选择签名选项。

  6. 确认信息。

  7. 点击「Upload」。

  8. 等待上传完成。

方式二：Transporter 上传

  1. 从 Mac App Store 下载 Transporter。

  2. 登录 Apple ID。

  3. 将导出的 IPA 拖入 Transporter。

  4. 点击「交付」。

  5. 等待上传完成。

方式三：命令行上传

xcrun altool --upload-app \
  --type ios \
  --file /path/to/app.ipa \
  --username &quot;your@email.com&quot; \
  --password &quot;app-specific-password&quot;

说明：

  • 需要 App 专用密码。

  • 适合自动化流程。

  • 推荐使用 Transporter 或 Xcode。

七、导出 IPA

如果需要本地保存 IPA 或用于 Ad Hoc 分发。

导出步骤：

  1. 在 Organizer 中选择 Archive。

  2. 点击「Distribute App」。

  3. 选择分发方式：

- App Store Connect - Ad Hoc - Enterprise - Development

  1. 选择签名选项。

  2. 选择导出位置。

  3. 点击「Export」。

IPA 文件结构：

MyApp.ipa
├── Payload/
│   └── MyApp.app/
│       ├── Info.plist
│       ├── 资源文件
│       └── 可执行文件
└── SwiftSupport/（如使用 Swift）

注意：

  • Ad Hoc 分发需要提前注册设备。

  • Enterprise 分发需要企业账号。

  • 导出后可通过 Apple Configurator 或第三方工具安装。

八、上传后处理

上传成功后：

  1. 登录 App Store Connect。

  2. 进入「我的 App」。

  3. 选择对应 App。

  4. 进入「活动」或「版本」页面。

  5. 查看构建版本状态。

构建版本状态：

状态

说明

正在处理

无效

处理时间：

  • 通常 5-30 分钟。

  • 首次上传可能更久。

  • 处理完成后会收到邮件通知。

选择构建版本：

  1. 在版本页面，选择「构建版本」。

  2. 选择刚上传的版本。

  3. 保存。

提交审核：

  • 填写版本信息。

  • 上传截图。

  • 确认隐私声明。

  • 点击「提交以供审核」。

版本更新：

  1. 修改 Version 和 Build。

  2. 重新 Archive。

  3. 上传新构建版本。

  4. 在 App Store Connect 选择新构建版本。

  5. 提交审核。

注意：

  • 同一版本号可以有多个构建版本。

  • 已上架的版本不能修改。

  • 审核期间不能修改版本信息。

📌 进阶内容：自动化上传（fastlane / xcodebuild / altool）属进阶内容，已放到第 10 章《持续集成与交付》，基础篇手写上传即可。

十一、避坑指南

  • Archive 前先 Clean：避免缓存问题。

  • Build 号必须递增：否则上传失败。

  • 验证通过再上传：节省时间。

  • 上传时保持网络稳定：避免中断。

  • 注意邮件通知：处理失败会发邮件。

  • 不要重复上传同一构建版本：会提示重复。

  • 上传后耐心等待处理：不要反复操作。

  • 保留 Archive：便于后续导出和排查。
